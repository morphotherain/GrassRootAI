# 模块划分（逻辑模块 + 依赖规则）

> **目的**：给 EVE 体量下的每个玩法域一个「家」，让 AI/人实现功能时有明确落点。  
> **不要求**立刻搬物理目录；**要求**新代码先选 Domain，并遵守依赖方向。  
> 上位地图：[[EVE域地图]]

---

## 1. 垂直分层

```text
Host/                     GameApp、Scene FSM、Save attach/detach
Presentation/             UIF（主菜单）、UI（游戏内窗）、Scene 渲染
Command/                  Task、TaskParams、TaskMgr 路由

SimulationKernel/         SolarSystem 会话、Entity 生命周期、System 调度
WorldModel/               GameObject、Component、Archetype、ObjectFactory

Data/
  Static/                   inv、dogma、map、industry…
  Dynamic/                  dyn* 存档表
  Dogma/                    类型/属性/effect 门面（强烈建议独立）

Domain/                     见 §2（EVE 玩法域）
```

### 依赖方向（硬规则）

```text
Presentation  →  Command  →  Domain/*  →  WorldModel  →  Data
SimulationKernel 编排 Domain 的 System，不实现业务规则
Universe/* 提供 ContentRules；Combat/Mission/PvE 读 rules，不硬编码空间类型
Social / Sovereignty 不得被 UI 直接写状态
```

| 从 | 不可依赖 |
|----|----------|
| Presentation | Domain 内部、SolarSystemMgr 私有状态 |
| Domain | D3D、UIWindow、Scene 渲染 |
| Data | UI、Task Handler |
| SimulationKernel | 具体 Market/Industry 业务 if-else 树 |

## 3. 模块 Charter 模板

每个域在扩展功能前，应能回答下表（可写在 PR 或子文档）：

| 项 | 说明 |
|----|------|
| **职责** | 一句话 |
| **拥有状态** | dyn 表 / Component / 内存单例 |
| **Command 入口** | TaskType / handlerType 列表 |
| **允许依赖** | WorldModel、Data、TaskParams… |
| **禁止依赖** | UI、D3D、其它 Domain 的内部类 |
| **禁止放入** | 哪些邻域逻辑不能塞进来 |
| **SpaceKind** | 在哪些空间类型下生效 |
| **MVP 状态** | 核心 / 占位 / 不做 |

## 4. 核心模块 Charter（摘要）

### 4.1 Data / Dogma

- **职责**：typeID → 组/类别/默认属性；将来 modifier、effect。
- **拥有**：`InvTypes*`、`dogma*`、`GenericChain`。
- **禁止放入**：战斗结算、UI 布局、Task 路由。
- **现状**：表分散在 `Database/DataSheet/`；新代码应经 Dogma 门面读，避免 Component 内重复查表。

### 4.2 SimulationKernel

- **职责**：加载/卸载太阳系、调度 System、Task 分发给 Entity/Handler。
- **拥有**：`SolarSystemMgr`、`SolarSystem`、`EntityUpdateSystem`、`SectorSpatialSystem`。
- **禁止放入**：Market 撮合、Mission 目标检查、Sov 计时。
- **现状**：`SolarSystemMgr::handleTask` 应只做路由 delegate。

### 4.3 Universe / KSpace

- **职责**：恒星系实例、sector、静态天体、星门。
- **拥有**：`SolarSystem` 对象表、`mapSolarSystems*`。
- **Command**：`handlerType` create/transfer/destroy（Inventory 跨界）。

### 4.4 Navigation

- **职责**：跃迁、接近、停靠、跳门、离港。
- **Command**：`setApproachTarget`、`setWarpTarget`、`jump`、`dock`、`undock`。
- **禁止放入**：锁定列表、Market 订单。

### 4.5 Combat

- **职责**：锁定、武器、伤害、装备激活。
- **拥有**：`LockingComponent`、`WeaponComponent`、`Equipment*`。
- **历史债**：`cargoStorage` + `direction` 路由到 Locking — 应迁到 Navigation/Input，文档标记待收。

### 4.6 Fitting

- **职责**：槽位、安装/卸载、组→槽映射。
- **拥有**：`EquipmentsComponent`、`*SlotComponent`、`invEquipmentGroupSlots*`。
- **Command**：`equipments` / `installEquipment` / `switch`。

### 4.7 Inventory

- **职责**：物品在哪（container 链）、堆叠、create/transfer/destroy。
- **拥有**：`dynGameObjects`、`dynContainers`、`StorageComponent` 系列。
- **Command**：`transferObject`、`createObject`、`cargoStorage`、`addObject`。
- **详见**：[[数据与对象模型评估]]

### 4.8 Industry / Market / Mission / …

- **Industry**：`RefiningSystem`、industry 表；制造/发明将来独立 System。
- **Market**：`dynMarketOrder*`；**必须有** Service 层，禁止 UI 直写 SQL。
- **Mission**：占位；与 `Universe/Instance` 联动。
- **Sovereignty / Social / WH / PI**：占位，见 [[EVE域地图]]。

### 4.9 NPC

- **Core**：spawn/despawn、loot 表、AI tick。
- **Archetype**：Rat / Agent / Sleeper 分行为包；禁止单文件 `NPC.cpp` 吞全部。

### 4.10 Presentation

- **UIF**：主菜单、存档（Phase B/C 已完成）。
- **UI**：游戏内窗；**只发 Command**，不直改 Mgr。
- **Scene**：渲染循环；少改模拟状态。

## 6. 给 AI 的硬规则

1. **新功能**：先选 **SpaceKind** + **Domain**，再写文件。
2. **跨 Domain**：用 Command 链或 Kernel 编排；禁止新建 `XxxMgr` 杂物间。
3. **单文件 >400 行且含两种 Domain 关键词** → 拆或抽 Service。
4. **UI 写 dyn 表** → 不通过（读表展示可以，改状态必须 Task）。
5. **`SolarSystemMgr` 新方法** → 只允许路由/delegate。
6. **新 Command 参数** → `TaskParams.h` + `Document/任务/`。
7. **EVE 对照**：「这在 EVE 里属于哪个系统？」— 星图≠市场≠装配≠Mission。

## 7. 物理目录策略

| 阶段 | 做法 |
|------|------|
| **现在** | 逻辑模块 = 本文 + Charter；文件头可写 `// Domain: Inventory` |
| **新功能** | 优先 `include/Domain/<Name>/` 放新 System/Service/Handler |
| **旧代码** | 可留原路径，不强制大爆炸搬迁 |
| **禁止** | 为「模块好看」而全量改 include 导致 Rebuild 地狱 |
