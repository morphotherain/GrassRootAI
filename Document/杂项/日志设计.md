# 日志设计

> 配合 `include/log/logger_manager.h`（`DEBUG_` / `INFO_` / `WARN_` / `ERROR_`）与 `include/log/SimLog.h`（域前缀宏）。

## 目标

- **边界可追踪**：进游戏、回主菜单、Task 分发、场景切换，看 log 能串成时间线
- **Release 可用**：边界用 INFO/WARN，不依赖海量 DEBUG
- **低噪声**：不在 UI 每帧、不在热路径每 tick 打日志

## 日志级别

| 级别 | 用途 | Release 默认 |
|------|------|--------------|
| `ERROR_` | 不可恢复 / 流程失败（读档失败、detach 失败） | 开 |
| `WARN_` | 异常但可继续（Task 未命中 handler、依赖未注入） | 开 |
| `INFO_` | 边界锚点（进游戏、Shutdown、场景切换） | 开 |
| `DEBUG_` | 开发细节（组件依赖解析、UI 调试） | 关（或 spdlog level） |

初始化：`Main.cpp` → `initLogging()`。调整级别可在 `initLogging` 内改 spdlog default level。

## 域前缀（SimLog.h）

| 宏 | 域 | 打在哪里 |
|----|-----|----------|
| `LOG_SAVE` | 存档 | `EnterGameFromSlot` / `ReturnToMainMenu` / SaveGameManager 失败 |
| `LOG_SIM` | 模拟 | `SolarSystemMgr::Init` / `Shutdown`、对象数摘要 |
| `LOG_TASK` | 任务 | `SolarSystemMgr::handleTask` 分发结果 |
| `LOG_SCENE` | 场景 | `SceneTransitionService` 决定切换时 |
| `WARN_TASK` | 任务 | Entity / Mgr handler 未命中 |
| `WARN_SIM` | 模拟 | 依赖注入失败等（按需） |

**写法示例**：

```cpp
LOG_SAVE("读档成功 slotID={}", slotID);
LOG_TASK("分发 targetSystem={} taskType={} publisher={} target={}", ...);
WARN_TASK("SolarSystem handler 未命中 handlerType=\"{}\"", handleType);
```

## 边界锚点清单（Phase 0.3）

### 存档 / 游戏状态（GameApp）

| 事件 | 级别 | 内容 |
|------|------|------|
| 开始读档 | INFO | slotID、GameState |
| 进入 InGame | INFO | slotID |
| 返回主菜单 | INFO | 触发 teardown |
| 读档/ detach 失败 | ERROR | 原因 |

### 模拟层（SolarSystemMgr）

| 事件 | 级别 | 内容 |
|------|------|------|
| Shutdown 前 | INFO | `p_mapObject.size()`、太阳系数量 |
| handleTask SOLAR_SYSTEM | INFO | handlerType、是否命中 |
| handleTask → Entity | DEBUG 可选 | task 摘要 |
| handler 未命中 | WARN | handlerType 或 taskType |

### Entity Task（DispatchEntityTask）

| 事件 | 级别 | 内容 |
|------|------|------|
| taskType 无注册 | WARN | taskType、publisherId、targetId |
| taskType 为空 | 静默 | 占位 handler |

### 场景（SceneTransitionService）

| 事件 | 级别 | 内容 |
|------|------|------|
| 决定切换 | INFO | from → to、containerID、solarSystemID |

## 不要打日志的地方

- UI `UpdateUI` 每帧（如滚轮 delta）→ 删除或 `#ifdef _DEBUG`
- `GetComponent` 热路径
- 已成功节流的 `BaseComponent::store` 内部

## 与 EventLogManager

`EventLogManager` 面向**游戏内事件队列**（UI/玩法），与 spdlog **诊断日志**分开。边界诊断走 SimLog；玩家可见日志走 EventLog。
